# Decisions and lessons, Sprint 7 (T-063, T-065 to T-072)

Records in the `decision-record` format. Sources are the tasks' Design and Review log; PR numbers are on main. Pointers only: no chat text, no company data. Brain repo copy: not written (a write to another repo is a human gate); Merwyn decides if it is wanted.

## D1. One published artifact is the single source of truth
Decision: the published "AI Office" page is one generated build (`--ledger <session> --chat`); the committed `office.html` stays the synthetic dev build for tests, golden and `--check`.
Context: Merwyn asked for one artifact and one source of truth. The ledger grows every session and planning PRs must not rebuild pages.
Options: A, commit the combined page (stale on every append, breaks planning-only PRs). B, generate it and keep the synthetic committed page (stable tests).
Chosen: B, because the ledger file is the data and the page is derived from it.
Consequences: republishing is Janice's manual step; the size limit applies only to the synthetic page; combining several session ledgers needs a new task. Reverses T-063's line "the recorded usage page never has chat". Budget reference raised to 8M by Merwyn (26 Nov).
Links: T-065 (PR #57), T-063 (PR #54).

## D2. Chat is docked below the office, not a floating panel
Decision: chat docks under the bar through a `--chat-h` CSS variable on the existing absolute layout; the office resizes (renderer resize coalesced to one per frame); height is adjustable and saved per viewer.
Context: the T-063 floating panel covered the office and was a full-screen sheet on phones.
Options: A, flex-column rewrite of the shell (more churn, no user gain). B, a "docked" mode on the T-059 panel (two code paths). C, variable on the existing layout.
Chosen: C, the smallest change; it reuses the T-059 clamp maths and keeps saved state backward compatible.
Consequences: chat left `PANEL.IDS`; the stage keeps a minimum height (240 desktop, 160 phone); minimum chat height is measured, not guessed. Supersedes the panel form in T-063.
Links: T-066 (PR #60), T-063.

## D3. No-overlap placement for HUD parts
Decision: every HUD part gets its own rectangle from one pure placement function (`C.place`), in priority order (bar and chat, open sheet or menu, focus card, usage, latest events); parts yield by shrink, collapse, then chip; short windows hide transient layers; on phones one layer at a time. Saved panel rects are never rewritten.
Context: when chat shrank the stage, usage spilled over latest events and the focus card; Merwyn asked for no overlap.
Options: A, absolute-paint the flow layout too (one path, but rewrites T-059 defaults and golden). B, CSS only (cannot handle the focus card or saved panels). C, one pure function over the flow layout.
Chosen: C, one testable rule with the least change to T-059 and T-066.
Consequences: page limit raised to 232 KB (237,568 B) with the reason recorded; the next raise needs a split or minify record first; a fixed-point test over `build()` and one 1280x480 one-frame overlap are open follow-ups.
Links: T-067 (PR #66), T-066.

## D4. Lean path for small changes
Decision: a task that qualifies skips only the separate PM spec run; the Architect writes a short Spec and Design in one run and the PMO still approves before build. Design, build and review are never skipped.
Context: T-066 took 7 runs and about 520k tokens; small one-surface changes did not need a separate spec.
Options: A, a new `lean` stage (changes the status set and board). B, a frontmatter `path:` key (needs a merge-rule change). C, a PMO dated note in the task body, checked by `validate`.
Chosen: C, because planning notes are already planning-only, so the merge rule is unchanged and the check is mechanical.
Consequences: one fewer run per small task; the text checks are a floor, so Architect, Reviewer or PMO can escape to the full path; saving is unmeasured until the first lean task (PMO compares against T-066 at sprint close). T-072 was the first.
Links: T-068 (PR #64), `workflow.yaml` `paths.lean`.

## D5. Usage is mirrored to the artifact db
Decision: usage reaches the page from the artifact db under an owner-only `usage` rule, synced one way from the repo ledger by Janice (`usage plan`, stdin only, byte-packed chunks); the build embeds only a fixed-size snapshot as fallback.
Context: every ledger append needed a republish, and the published page grew about 256 B per run.
Options: A, one doc per run (simple diff, one write per run, 25k-run cap). B, chunks (2 writes per sync, last chunk rewritten). C, keep republishing (no db, page keeps growing).
Chosen: B, fewer writes and the limits stay far away.
Consequences: the repo ledger stays the source and the db copy is a mirror; staleness is defined against the build and "last synced" shows on the page; the page depends on a sync step; the size guard moves to the template code. Retention of the db copy has no purge (question left to Wulan). Compliance U1a passed.
Links: T-069 (PR #73), T-065, T-063.

## D6. Main-session usage is a separate unit
Decision: main-session usage is a `kind:"main_session"` ledger line from the explain-usage reading, shown in its own row ("metered") and never added to agent tokens, totals or budgets.
Context: the main session's tokens were "not reported". explain-usage now reports input, cache write, cache read and output since the last context summary.
Options: A, a header field (header is append-only). B, a run line with agent `pmo` (mixes units, breaks the run invariant). C, a separate line kind.
Chosen: C, because the four parts have different prices and unknown overlap with subagent tokens, so any single sum would be an estimate.
Consequences: readings are cumulative per window, windows add; the PMO appends one line per explain-usage run; Detail view is about 67 px taller (usage panel collapses sooner; follow-up).
Links: T-070 (PR #70).

## D7. Tests never pin the live ledger
Decision: a test that reads the live ledger checks only properties that survive a valid append; exact numbers come from `tests/fixtures/session_FIXTURE072.jsonl`; a guard subclass runs the live checks on a temp copy with appended lines.
Context: honest appends (runs 101 to 106, a main-session line) failed 10 tests. Same class as T-055 and T-061.
Options: A, re-pin after each append (cheap now, breaks again). B, invariants plus fixture plus guard.
Chosen: B, because the ledger is append-only by design.
Consequences: new ledger-reading tests must follow the rule (see `engine/schema/usage.md`); `test_metrics` and `test_budgets` have no appended-ledger guard yet; the page's used figure leaves out chat-run tokens (PMO to decide).
Links: T-072 (PR #71), T-055, T-061.

## Lessons (each with a proposed edit; none applied here)
L1. Hard-coded tests broke main three times (T-055 sprint close, T-061 ledger append, T-072 ledger append). Proposed: add to `engine/schema/usage.md` and `review-checklist` the rule "a test over growing data checks invariants; pin exact values only on a fixture", and have the Reviewer run the suite on a temp copy with one appended line. Owner: Fang (rule), Cahyani (checklist). Partly done by D7.
L2. The chat inbox went unchecked for about 3 hours while agents ran (sprint-07 PMO note). Proposed: pmo-playbook section 9 says "check the inbox after every merge and every agent wait over 10 minutes, and write `running` and `last_inbox_at` each time". Owner: Janice.
L3. Size estimates ran 3 to 4x low (T-066 +2 KB est, +4.0 KB real; T-067 3.5 KB est, 14.6 KB real; T-069 3.5 KB est, about 6 KB real). Proposed: architect-playbook says "multiply a page-bytes estimate by 3, state the stop line, and measure a spike before the Design commits to a limit". Owner: Fang.
L4. Resumed agents may double-count tokens: the harness figure can include the earlier run (sprint 7 runs 39 and 40, up to 285,812 tokens counted twice). Proposed: pmo-playbook says "prefer a fresh agent for rework; if resuming, note it on the ledger line and record the delta". Owner: Janice. Related: D6 keeps main-session tokens out of the sum for the same reason.
